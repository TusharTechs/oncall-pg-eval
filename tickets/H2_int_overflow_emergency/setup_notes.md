- **Incident context.** There is also a table, created as:
```sql
CREATE TABLE events(id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, order_id bigint NOT NULL,
                    kind text NOT NULL, created_at timestamptz NOT NULL DEFAULT now());   -- 2,000,000 rows
```
  Its identity sequence (`events_id_seq`) has about **5,000 values left** before the `integer` maximum, and the existing ids are the 2,000,000 integers just below that point. The app inserts one `events` row per transaction (see the workload below), so at current traffic **inserts into `events` start failing in roughly 25 seconds**. In this ticket the analytics job reads `events` (not `orders`).
